## 2. Architecture & Backend Guarantees

### A. SHARED OPERATION CONTRACT v1
1. **Extended `QueueWorker.add_task` Signature**:
   ```python
   def add_task(
       self,
       task_type: str,
       filepath: str,
       dest_folder: str | dict[str, Any] | None = None,
       undo_token: dict[str, Any] | None = None,
       *,
       operation_id: str | None = None,
       task_options: dict[str, Any] | TaskOptions | None = None,
   ) -> str
   ```
   - Positional legacy signature remains fully supported.
   - Generates or accepts a unique `operation_id` string and returns it immediately for ID-based tracking.
   - Resolves `task_options` (including `view_generation` and `settings_snapshot`) at dispatch time.

2. **Unified Terminal `operation_result` Signal**:
   - `worker.signals.operation_result = pyqtSignal(dict)`
   - Emits exactly **one** logical terminal result per operation ID with `schema_version: 1`:
     - `schema_version`: `1`
     - `operation_id`: `str`
     - `action`: `str`
     - `source_path`: `str`
     - `destination_path`: `str | None`
     - `state`: `"completed" | "completed_with_warning" | "failed" | "recovery_required"`
     - `undo_token`: `dict | None` (versioned `version: 1`)
     - `error`: `str | None`
     - `warning`: `str | None`
     - `view_generation`: `int | None`

3. **Strict Signal Emission Ordering**:
   - Emissions follow a deterministic sequence:
     1. `progress.emit(msg)`
     2. `undo_record.emit(undo_token)` (if token present)
     3. `finished.emit(final_path)`
     4. `operation_result.emit(result_dict)`

---

### B. Provenance & Destructive Undo Guarantees
1. **Final Provenance Timing**: Destination file SHA-256 digest and file attributes are computed **AFTER** all AI EXIF and sidecar metadata updates are finalized on disk.
2. **Provenance Validation**: Destructive Undo verifies target file size and SHA-256 hash against recorded provenance. Tampered or altered files trigger failure state (`"failed"`) without restoring over corrupted targets.
3. **Collision Refusal**: If a restoration target path already exists on disk during `undo_move` or `undo_trash`, the operation is aborted safely with `FileExistsError` without overwriting user data.

---

### C. Safe Metadata I/O (`metadata_io.py`)
1. **Sidecar Preservation**: Reading preexisting `.txt` sidecars and merging new tags without clobbering human text notes or duplicating tags.
2. **Path Traversal Guard**: Canonical path checking ensures target sidecars cannot escape the parent image directory (`os.path.commonpath([parent_dir, real_sidecar]) == parent_dir`).
3. **EXIF Safety**: Embeds XPKeywords using double-null UTF-16LE encoding and enforces 32KB payload limits.
4. **Malformed EXIF Fallback**: Handles invalid camera EXIF headers gracefully without wiping existing non-EXIF image data.

---

### D. Durable Operation Journal (`operation_journal.py`)
1. **SQLite WAL Engine**: Stored at `get_data_dir() / "operation_journal.db"`.
2. **Explicit States**: Tracks lifecycle through `INTENT`, `STAGED`, `COMMITTED`, `COMPLETED`, `COMPLETED_WITH_WARNING`, `FAILED`, and `RECOVERY_REQUIRED`.
3. **Startup Crash Recovery (`reconcile_interrupted_operations`)**: Scans for non-terminal journal entries from prior process crashes. Cleans orphaned temporary artifacts without deleting ambiguous user files.
4. **Retention Bounds (`prune_journal`)**: Prunes terminal journal entries older than retention limits (default 30 days or max 10,000 entries).

---

### E. Source Lock Serialization
- Maintain a thread-safe map of locks keyed by canonical real path (`os.path.realpath(filepath)`).
- Concurrent or duplicate tasks targeting the same file execute sequentially and idempotently without race conditions.
